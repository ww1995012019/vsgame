# v1.4 动作与战斗判定修复

`street_duel_game_design.md` 是用户上传的完整设计参考。本轮用户明确选择「先修动作与战斗判定」，因此继续使用现有 Canvas/WebGL 工程与原画，不将参考文档中的全部后续功能视为本轮交付。

## 本轮实现

- 角色状态显式区分待机、前后移动、下蹲、起跳、腾空、落地、轻重攻击、技能、格挡、受击、击退与胜败。起跳、落地和硬直阶段限制可执行动作。
- 招式以 60 Hz 帧数据统一描述前摇、有效帧、后摇、伤害、硬直和取消窗口，动画读取同一招式数据。浏览器主循环与动作预览均按 1/60 秒更新。
- 攻击使用有效帧内的独立 Hitbox 与头、躯干、腿 Hurtbox 求交；弹体采用扫掠框；Pushbox 保持地面距离并处理墙角。双方同帧的接触先收集后结算。
- S/↓ 下蹲；受到威胁时按相对朝向的后方向站防，后+下蹲防。防御方向随换边更新，高/低/中段类型由配置决定。旧的显式 `block` 引擎输入继续兼容。
- 输入按发生顺序保留 8 帧。轻拳命中后可在配置窗口取消到重踢/技能，重踢可取消到技能；防御和空挥不提供命中取消。连击只在对手尚处于受控状态时延续。
- 升龙命中可挑空，落地进入缓冲后恢复；专用倒地、起身动画尚缺，不开放站立画面配地面受击框的倒地状态。普通跳跃没有基于根节点高度的伪无敌，腿部仍与弹体重叠就可受击。空中只开放有对应上半身动作的轻拳；空中踢腿暂未开放。
- 默认回合 99 秒；最大生命/能量、前后移速、跳速、重量、攻防倍率来自角色配置。
- F3 或「判定」按钮显示实际碰撞框、双方状态、招式帧、有效阶段和最近命中结果；B 显示驱动网格的骨骼。按键提示会随实际输入高亮。
- 保留原始角色图集；行走和跳跃沿用分区蒙皮与双腿 IK，攻击上半身与空中双腿分别求解，头部使用独立原画来源。

## 需要如实保留的限制

仓库每人只有 8 个完整姿态图，没有完整分层身体、遮挡区域纹理或全套动作序列。目前是原图网格蒙皮、原画姿态资源与程序 IK 的组合，并非具备全部关节分层资源的专业角色动画工程。寒锋上半身采用原比例离散关键姿态，前摇守势、有效帧出拳、后摇守势，缺少补间资源，不能称为连续的完整骨骼出拳动画。空中轻拳保持跳跃腿姿；完整空中踢腿、翻倒、起身等动作仍需要补画资源。

Hurtbox 是独立的身体分区近似框，尚未逐张原画精调。它不使用整张图片矩形，也不表示所有可见手指、衣摆都可受击。具体招式平衡、逐帧人体轮廓和专业动画审校仍需后续迭代。

本轮没有新增全套普通技、超必杀、完整训练设置、回放、音频素材或联网；保留原有训练、AI 与合成音效。参考文档中的这些内容未标为已完成。

## 可复核方式

1. 在训练场按 F3，J/K/L/O 出招。前摇与后摇没有近身攻击框，有效帧显示红框；蓝框为 Hurtbox，黄框为 Pushbox。
2. 按住 S 下蹲，再按相对后方向；换边后检查后方向变化。只下蹲不自动防御。
3. 轻拳命中后及时输入重踢，再取消到技能，检查真连击；等受击方恢复后再打应重新计数。
4. 在 `public/motion-review.html` 用 0.25 倍、暂停、下一帧和骨骼开关检查原人物行走、跳跃及技能。
5. 执行 README 中的逻辑和浏览器测试，检查原图 SHA-256、动画过渡、碰撞有效帧、状态限制和实际输入。
