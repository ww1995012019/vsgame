# 《街头对决》格斗游戏开发需求文档

版本：V1.0  
用途：交给其他 AI 编程助手，作为可执行的游戏开发任务书。  
视觉依据：用户上传的《街头对决》训练场截图。

## 1. 项目目标

制作一款真正可玩的 1v1 横版格斗游戏。整体视觉沿用参考图：雨夜东方古街、霓虹灯笼、湿润石板路与倒影、两名动漫风格角色左右对峙、顶部双方血条、中间计时器、左侧训练信息面板、底部键位提示和操作按钮。

**首版必须是可玩的游戏，而不是只有 UI 的静态网页。** 玩家应能移动、跳跃、防御、攻击、命中对手、造成伤害，并完成胜负判定和重新开始。

首版范围：
- 单机 1P 对战 AI。
- 自由训练模式。
- 标准对战模式，含生命值、倒计时、KO 和胜负结算。
- 至少两个可选角色。
- 键盘操作，预留手柄和触屏扩展。
- 暂不做联网匹配、账号、商城、剧情和复杂养成。

## 2. 游戏定位

| 项目 | 规格 |
|---|---|
| 类型 | 2D 横版 1v1 格斗，2.5D 场景表现 |
| 视角 | 固定侧视，双方始终面向对手 |
| 平台 | 首版 PC 浏览器或桌面端 |
| 画面比例 | 16:9，自适应 1440×900 / 1920×1080 |
| 美术 | 东方街头武侠、动漫卡通渲染、街机格斗 |
| 核心体验 | 易上手、有打击感、连招反馈明确 |
| 首发模式 | 训练场、AI 对战 |
| 单局时长 | 默认 99 秒，可配置 |

## 3. 美术与场景

### 3.1 场景风格

制作有纵深的雨夜东方古街：
- 两侧为传统木质商铺、屋檐、窗户、灯笼和竖向招牌。
- 远景有街道纵深、建筑轮廓、雨雾和暖色灯光。
- 中景可有围观人群剪影，但不能遮挡角色。
- 地面为湿润石板路，呈现青蓝、橙红色霓虹倒影。
- 持续雨线、落地水花、少量雾气和灯光闪烁。
- 冷青色环境光与暖黄色灯光形成对比。

图层建议：夜空远景、远景建筑、中景建筑和招牌、人群、战斗地面、角色、前景雨滴、HUD。背景可有轻微视差，但战斗地面必须稳定，角色脚底始终落在同一条地面基线上。

### 3.2 角色画风

角色采用高精度动漫格斗游戏风格，轮廓清楚、动作有力度，人物必须明显区别于背景。优先使用逐帧 Sprite 或骨骼动画；不能用静态立绘简单平移冒充格斗动作。

## 4. UI 设计

### 4.1 顶部导航

左侧：黄色锐利 Logo、“街头对决”和英文副标题 STREET DUEL。  
中间：对战大厅、角色、排行榜、训练场；当前页面用黄色文字、底部黄线和细黄框高亮。  
右侧：玩家头像、昵称、在线状态和下拉入口。首版可使用本地假数据。

### 4.2 战斗 HUD

屏幕顶部左右对称：
- 左侧玩家头像、P1 标识、角色名、黄色生命条。
- 右侧对手头像、角色名、红色生命条。
- 血条下方显示能量条。
- 中央显示计时器；训练模式显示 ∞ 和 TRAINING。
- 命中时血条短暂闪烁，扣血平滑过渡。
- 显示连击数、回合提示、KO、胜利/失败提示。

### 4.3 左侧训练面板

深色半透明底和黄色细边线，包含 TRAINING MODE、自由练习、累计伤害、命中次数、无限时间、能量恢复开关、静止回血开关和重置训练按钮。面板不能遮挡角色主要动作，并支持隐藏/显示。

### 4.4 底部操作栏

左侧显示当前模式和训练状态。中部显示键位：
- `W A S D`：移动 / 防御方向。
- `J`：轻攻击。
- `K`：重攻击。
- `L`：技能攻击。
- `O`：特殊技 / 超必杀。
- `ESC`：暂停。

右侧放置黄色“重新开始”按钮和描边“设置”按钮。按键提示必须与真实输入绑定，按下时对应按键高亮。最底部可显示 FPS、音效开关和版本号；正式模式默认隐藏 FPS。


## 5. 首发角色

### 5.1 烈影：敏捷型

外观：年轻格斗家，深色短发、黄色短外套、黑色内搭、黑色宽松格斗裤（金色纹样）、红色护手和运动格斗鞋。

特点：移动快、轻攻击启动快、连招容易衔接，单次伤害中等，擅长突进和连续攻击。

招式：轻拳（快速直拳）、轻腿（快速低踢）、重拳（蓄力摆拳）、重腿（转身踢）、技能一（赤焰突进）、技能二（连续拳影）、超必杀（烈影连击）。

### 5.2 寒锋：力量型

外观：白灰短发、强壮体型、深蓝无袖格斗服、白色宽松格斗裤（红色纹样）、红色腰带和深色格斗靴。

特点：移动略慢、普通攻击伤害高、重攻击硬直明显、防御稳定，擅长强力打击和范围压制。

招式：轻拳（短距离刺拳）、轻腿（前踢）、重拳（强力直拳）、重腿（高位回旋踢）、技能一（崩山拳）、技能二（震地冲击）、超必杀（寒锋破阵）。

角色属性必须配置化：角色 ID、名称、最大生命值、前进速度、后退速度、跳跃速度、重量、攻击倍率、防御倍率、最大能量。新增角色时不应修改核心战斗系统。

## 6. 核心战斗系统

### 6.1 角色状态机

至少实现：Idle、WalkForward、WalkBackward、Crouch、JumpStart、Jump、Landing、LightAttack、HeavyAttack、SkillAttack、Block、Hit、Knockback、Knockdown、GetUp、Victory、Defeat。

使用明确状态机管理角色行为。受击、倒地、技能释放期间，不得随意切换成普通移动。

### 6.2 移动与朝向

- 左右移动、跳跃、下蹲。
- A/D 根据角色当前朝向映射为前进/后退，不能永远把 D 当成前进。
- 双方自动面向对手。
- 双方有最小间距，不能穿透彼此。
- 角色不能超出场景边界。
- 支持地面攻击和有限的空中攻击。
- 角色落地后恢复地面状态。

### 6.3 攻击判定

战斗逻辑与动画表现必须分离。每个招式独立配置：
- Startup：启动帧。
- Active：有效帧。
- Recovery：收招帧。
- 攻击框 Hitbox、受击框 Hurtbox。
- 攻击高度、伤害、击退距离。
- 命中硬直、被防御硬直。
- 是否可取消到其他招式。

必须通过 Hitbox 与 Hurtbox 检测命中，不能用整张角色图片的矩形代替攻击判定。命中后扣血、播放受击动画、产生击退和音效。

调试模式必须显示角色碰撞框、攻击框、受击框、当前状态、招式帧数和命中结果。

### 6.4 连招与输入缓冲

- 支持轻攻击接重攻击、普通攻击取消到技能。
- 按招式规则衔接跳跃攻击和地面攻击。
- 输入缓冲建议 6–10 帧，可配置。
- 记录输入顺序和时间，避免按键稍早导致招式无法触发。
- 连击时显示 Combo x2、Combo x3；连招结束后清空计数。
- 首版先做固定连招，不要求复杂指令识别。

### 6.5 防御、受击和倒地

- 按住后退方向进入站立防御，下后方向可进入下段防御。
- 防御成功时按攻击类型计算格挡伤害或完全抵挡。
- 被攻击后进入受击硬直；强攻击造成更明显击退。
- 连续受击或特定技能可触发击飞、倒地。
- 倒地后经过配置时间自动起身。
- 防御不能在所有攻击动作中无条件取消。

### 6.6 能量和打击感

普通命中、成功防御或受到攻击可积累能量；技能消耗指定能量，超必杀需要满能量。训练模式可设置能量无限。

命中反馈组合使用轻微屏幕震动、命中闪光、短暂 hit-stop、受击动作、击退、打击音和连击提示。重攻击与超必杀反馈更强，但普通攻击不能每次都大幅震屏。

## 7. 训练模式

训练模式是首版重点：
- 无限时间。
- AI 可设为不攻击、被动或正常。
- 生命值自动恢复开关。
- 能量自动恢复开关。
- 重置双方位置和状态。
- 累计伤害、命中次数、最高连击统计。
- 显示/隐藏碰撞框。
- 重置训练数据。

训练模式不触发正式胜负结算；角色生命值归零时可按设置自动恢复。

## 8. AI 对手

首版使用有限状态逻辑，不需要机器学习：
- Idle：等待。
- Approach：距离太远时接近。
- Attack：进入攻击范围后选择招式。
- Block：检测玩家攻击时有概率防御。
- Retreat：生命较低或需要拉开距离时后退。
- Recover：受击或倒地时等待恢复。

难度分为简单、普通、困难。简单反应慢、攻击少；普通会接近、攻击和基础防御；困难会使用连招和技能，但不能读取玩家未来输入。AI 必须遵守与玩家相同的攻击判定、硬直和资源规则，不能作弊穿透或无条件命中。

## 9. 游戏流程

训练模式：进入训练场 → 选择双方角色 → 加载场景 → 初始化位置和属性 → 自由练习 → 随时重置或退出。

标准对战：角色选择 → 加载场景 → 回合开始提示 → 倒计时 → 战斗 → 生命值归零或时间结束 → 判定胜负 → 结果面板 → 再来一局 / 返回角色选择。

时间结束时生命值较高者获胜，相同则平局。ESC 打开暂停菜单：继续、重新开始、设置、返回主菜单。暂停时停止计时、角色逻辑和 AI 决策。

## 10. 音效

至少准备雨声、街道环境音、背景音乐、轻拳、重拳、踢击、格挡、受击、技能释放、技能命中、KO 和胜负提示音。设置中提供音乐音量、音效音量和静音开关。同类音效需要限制并发，避免连续攻击时声音无限叠加。


## 11. 技术实现建议

### 11.1 推荐技术路线

**推荐 Godot 4.x。** 格斗游戏需要可靠的帧更新、状态机、碰撞判定、动画控制和桌面打包能力，Godot 更适合做完整游戏。

核心模块建议：
- `GameManager`：模式、回合流程、胜负。
- `Fighter`：角色实体和状态机。
- `FighterController`：玩家输入。
- `AIController`：AI 决策。
- `CombatSystem`：攻击判定、伤害、硬直、击退。
- `MoveData`：招式帧数据和属性。
- `AnimationController`：动画播放与动画事件。
- `HUDController`：血条、计时器、连击显示。
- `TrainingManager`：训练设置和统计。
- `AudioManager`：音乐与音效。
- `StageController`：场景、雨效、镜头和背景层。

若必须运行在浏览器，可使用 TypeScript + Phaser 3；战斗更新仍应采用固定时间步进，不要依赖 DOM 动画。

### 11.2 更新规则

- 战斗逻辑固定 60 FPS，渲染与逻辑更新分离。
- 攻击帧数据以 60 帧为基准。
- 输入系统记录按键状态和输入缓冲。
- 暂停时停止逻辑更新。
- 不可用不稳定的帧间隔直接累加攻击帧数。

### 11.3 数据驱动

角色、招式、AI 难度、训练配置和按键映射均使用 JSON / Resource 配置。新增角色时尽量不修改核心战斗系统。

## 12. 资源清单

**角色资源：** 两名角色的待机、前进、后退、跳跃、下蹲、轻拳、重拳、轻腿、重腿、技能、受击、击退、倒地、起身、胜利、失败动画；头像和选择界面立绘。

**场景资源：** 雨夜古街远中近景、地面反光、灯笼、招牌、建筑装饰、人群剪影、雨线、水花和雾气。

**UI 资源：** Logo、头像框、血条、能量条、训练面板、按键提示、按钮、暂停菜单、胜负面板。

**音频资源：** 背景音乐、雨声、拳脚、格挡、受击、技能和 KO 音效。

允许先用统一风格的临时素材占位，但必须保留清晰的资源替换接口。不能把静态角色图当作最终动作系统。

## 13. 开发阶段与验收标准

### 阶段一：战斗原型

完成两个可控制的占位角色、移动、跳跃、朝向、攻击判定、扣血、受击、格挡和胜负判定。

**验收：** 两个角色能互相攻击；攻击只有在有效帧命中；血量正确变化；角色不会穿透；KO 后结束本局。

### 阶段二：训练模式

完成无限时间、恢复生命值、恢复能量、重置位置、伤害统计、碰撞框调试。

**验收：** 可连续练习；重置后状态完全恢复；统计数据正确；训练模式不会误触发正式结算。

### 阶段三：角色与 AI

完成烈影、寒锋的差异化招式和动画；完成三档 AI。

**验收：** 两名角色属性和招式有明显差异；AI 能接近、攻击、防御和恢复；AI 遵守相同战斗规则。

### 阶段四：视觉与音效

完成雨夜古街、HUD、训练面板、底部按键栏、命中特效和音效。

**验收：** 画面布局与参考图高度一致；UI 不遮挡主要战斗区域；血条、计时器和键位提示实时准确。

### 阶段五：完善与交付

完成暂停、设置、角色选择、胜负界面、性能优化和构建说明。

**验收：** 从启动到角色选择、开战、结束、重开流程完整；无阻断性错误；提供可运行工程和启动说明。

## 14. 质量要求

- 不允许只交付静态 UI 或不可操作的演示动画。
- 不允许用随机扣血代替真实攻击判定。
- 不允许角色穿透、卡死、无限连击或状态无法恢复。
- 动画、判定框和伤害帧必须一致。
- 所有按钮必须可用，所有键位提示必须与实际操作一致。
- 分辨率变化时 HUD 不得错位。
- 关键战斗数值必须可配置。
- 项目结构清晰，模块职责明确，便于后续 AI 接手扩展。
- 每个阶段完成后先运行测试，再进入下一阶段。

## 15. 给执行 AI 的工作指令

请先完整阅读本需求文档，再检查当前项目目录和已有技术栈。不要一开始就生成全部内容，也不要只做 UI。

执行顺序：
1. 输出项目结构、技术选型和实现计划；如果已有项目，优先兼容现有架构。
2. 先完成阶段一的可玩战斗原型，并实际运行验证。
3. 每完成一个阶段，列出已完成内容、修改文件、运行方式和测试结果。
4. 遇到素材缺失时先创建可替换的占位资源，不要因此阻塞战斗系统。
5. 不得伪造测试通过结果；无法运行时明确说明阻塞原因。
6. 最终交付完整源代码、资源目录、启动/构建说明、操作说明和已知问题清单。

**最高优先级：先做出真正能打的格斗游戏，再逐步还原参考图的美术和 UI。**
